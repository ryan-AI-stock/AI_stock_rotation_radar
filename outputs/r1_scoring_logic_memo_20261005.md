# R1 分數統計邏輯 MEMO

日期：2026-10-05  
模型定位：research challenger／report-only  
用途：提供 ChatGPT 或其他研究者檢視 R1 的題材 Top3 與優先持有參考值設計。

## 一、R1要解決的問題

R1不是每日短線選股模型，也不直接給買進或賣出指令。模型的工作是：

1. 維護AI發展主要瓶頸題材與候選公司。
2. 每季找出每個題材的結構性Top1～Top3。
3. 每個交易日更新每檔股票0～100分的「優先持有參考值」。
4. 讓Ryan自行比較目前持股與其他題材龍頭，再決定是否換股。

R1目前有10個題材、50檔股票。題材與成分股每半年審查一次，程式只能提出增刪建議，Ryan核准後才能生效。

## 二、季度結構性Top3

每檔股票先計算「結構性龍頭分數」，滿分100分：

| 構面 | 權重 | 要回答的問題 |
|---|---:|---|
| AI瓶頸直接性 | 25% | 公司產品是否直接解決AI擴產、算力、頻寬、供電、散熱或材料瓶頸，而不是只具間接受惠題材？ |
| 產業與技術地位 | 25% | 公司是否具有市占、技術門檻、客戶認證、量產能力、不可替代性或龍頭地位？ |
| AI營收兌現 | 20% | AI需求是否已反映在營收、出貨、產能利用率、訂單或公司正式財測，而不只是故事？ |
| 財務與獲利品質 | 20% | 營收、毛利、營益率、EPS、現金流及資產負債是否支持長期成長？ |
| 市場代表性 | 10% | 公司在該題材是否具有足夠規模、流動性、法人關注與市場定價代表性？ |

公式：

`結構性龍頭分數 = 瓶頸直接性×25% + 產業技術地位×25% + AI營收兌現×20% + 財務獲利品質×20% + 市場代表性×10%`

同一題材內按分數由高到低排列，取Top1～Top3；同分時以股票代號作固定tie-break，避免結果不穩定。

### Top3發布閘門

- 同一題材所有候選股都必須完成五構面評估，才能公布Top3。
- 任一股票、任一構面缺資料，該題材維持`DATA_MISSING`。
- 缺值不得補0，也不得把剩餘權重重新分配。
- 不可因為市場普遍稱某公司為龍頭，就直接給高分。

## 三、每日優先持有參考值

季度Top3回答「誰是長期結構性龍頭」；每日優先持有值回答「以今天狀況，哪一檔相對值得優先持有」。滿分100分：

| 構面 | 權重 | 要回答的問題 |
|---|---:|---|
| 結構性龍頭 | 30% | 沿用季度結構性龍頭分數。 |
| 營收與獲利成長 | 25% | 月營收、EPS與獲利趨勢是否持續改善或上修？ |
| 估值相對自身歷史 | 20% | Forward PE等估值相對公司自身歷史是否合理，而不是拿不同產業的絕對本益比硬比？ |
| 股價風險安全度 | 15% | 股價是否過熱、乖離過大、位階過高，或處於相對可承受的位置？ |
| 需求、訂單與催化 | 10% | 近期是否有可驗證的需求、擴產、訂單、產品認證或產業供需催化？ |

公式：

`優先持有參考值 = 結構性龍頭×30% + 營收獲利成長×25% + 自身歷史估值×20% + 價格風險安全度×15% + 需求訂單催化×10%`

這個分數不是上漲機率，也不是買進、賣出、加碼或減碼指令。

## 四、資料與證據規則

每個非空分數都必須附上：

- `source_url`
- `source_date`
- `available_at`
- `source_family`
- `evidence_note`

只使用評估日當時已公開的資料。`available_at`晚於評估日即視為future-data violation並拒絕。公司官方資料、公開資訊觀測站、交易所資料優先；產業研究與市場共識只能補充，不能單獨決定龍頭。

更新頻率：

- 每個交易日：官方價格、成交金額、技術風險與市場資料。
- 每週最後交易日：EPS修正、法人籌碼、需求、訂單、催化與風險。
- 每季財報揭露後：重評題材Top1～Top3。
- 每半年：檢討題材與成分股，保留當時增刪證據。

## 五、目前已完成與尚未完成

已完成：

- 10題材、50檔候選池。
- 兩組權重與加權公式。
- 缺值不補0、證據欄位、PIT日期與future-data驗證。
- 50檔輸入materializer、季度排名程式、Dashboard與日／週排程。
- Dashboard只顯示研究結果，不啟用交易。

已建立、待外部檢視後凍結：

- `config/r1_v03_score_rubric.json`已建立第一版原始資料轉分契約。
- 季度「瓶頸直接性」採0／25／50／75／100證據階梯；75分以上至少需要兩類獨立來源。
- 財務品質先依絕對安全與成長門檻評估，再作同題材比較；不只靠題材內百分位硬排高低。
- 估值與股價風險以公司自身歷史百分位為主，避免跨產業用相同絕對本益比或股價位階比較。
- 程式已阻擋權重漂移、缺值重配權重、未來資料及自動交易啟用。

尚未完成：

- 五個季度構面與五個每日構面的第一版轉分契約仍需反例與敏感度檢查，尚未升為凍結正式規格。
- 50檔官方證據尚未全部補齊，因此目前Top1～Top3仍顯示「尚未產生」。
- 分數完成後仍需做敏感度、排名穩定性與反例檢查，避免主觀打分或權重造成假精確。

## 六、希望ChatGPT協助檢視的問題

1. 如何把十個構面各自轉成可重複、可稽核的0～100分，且符合台灣股票市場？
2. 哪些構面適合使用同題材內百分位，哪些應使用絕對門檻？
3. 如何避免小型高成長股與大型龍頭因規模差異產生結構性偏誤？
4. 如何避免媒體聲量、股價漲幅或事後資訊反向污染「AI瓶頸」與「龍頭」評分？
5. Top3是否必須等題材內所有股票資料完整，或可在明確揭露coverage時發布暫定排名？
6. 每日優先持有值應如何降低短期價格波動造成的頻繁排名翻轉？
7. 哪些stop-gate可以防止錯誤資料或單一來源讓分數失真？

## 七、治理邊界

- `formal_model_changed=false`
- `trade_decision_changed=false`
- `active_in_trade_decision=false`
- `report_changed=true`

R1不取代V4-D正式模型，也不改變C6研究版的每日交易決策。

## 八、版本邊界

本MEMO描述的是目前Dashboard使用的`R1 v0.3｜十大題材龍頭與優先持有參考值`。

程式庫中仍保留早期R1研究引擎，其五構面為「EPS修正、Forward估值、瓶頸、催化、價籌」。該引擎只保留歷史研究與資料累積，不等於本MEMO的季度五構面，也不得混入目前Dashboard的Top1～Top3或優先持有參考值。

在原始資料轉分表正式凍結、50檔證據補齊與敏感度驗證完成前：

- 不發布假精確的Top1～Top3。
- 不把`NA`或缺值補成0。
- 不把R1分數解讀成上漲機率。
- 不啟用自動交易或實際買賣指令。
